What is HERALD?

HERALD is the central orchestrator for all agentic task execution. It is the only agent with cross-system awareness. Every other agent has a single defined scope and communicates exclusively with HERALD — no agent communicates with another agent directly.

HERALD sits between human input and every downstream agent. It runs discovery, manages planning, controls the agent lifecycle, dispatches work, tracks execution state, and learns from every execution.

Fast-Track Mode

Three stacked mechanisms to reduce pipeline overhead for low-risk or time-sensitive work. Project config always takes precedence.

Fast-track decision tree — config overrides all
⚙️
Config Override

herald.config.json — set fast_track: false to enforce full pipeline on critical projects. Overrides all flags and classification.

⚡
/fast Flag

User prefixes request with /fast to skip discovery and context loading. Jumps straight to SA planning. Plan approval is never bypassed.

🧠
Auto-classification

HERALD classifies every request automatically — Simple, Moderate, or Complex — and applies the appropriate pipeline level.

LevelCriteriaPipeline applied
SimpleSingle file · No ambiguity · No new agents · No cross-system impact · Low riskSkip to dispatch
ModerateMultiple files · Some ambiguity · Existing agents sufficient · Limited cross-system impactSkip discovery, run planning + approval
ComplexNew agents needed · Cross-system · High risk · Unclear intent · Multiple viable approachesFull pipeline

Modes

Three slash commands that change how HERALD operates — without changing the pipeline's safety guarantees.

⚡
/fast

Skips discovery and context loading. Jumps straight to SA planning. Plan approval is never skipped. Use for low-risk, well-understood tasks.

🧠
/brainstorm

Structured thinking mode. Runs Critique → Design → Benchmark → Recommend. No agents dispatched, no plan created. Output can be promoted to a real plan.

✓
/score

Manually triggers Layer 6 if it was missed. Runs full scoring against the last completed plan — updates context store and conditionally stores pattern.

The Six Layers

Six-layer pipeline · left to right · full or fast-tracked
1
Intent

Intent Engine

  • Check herald.config.json — apply fast-track rules
  • If /fast used and enabled → skip to layer 3
  • Classify complexity: simple, moderate, or complex
  • Full discovery session across all 8 dimensions: Intent · Scope · Constraints · Stack · Format · Timeline · Dependencies · Risk tolerance
  • Do not proceed until all dimensions are answered or confirmed not applicable
2
Context

Context Harvester

  • Check plans/ for any plan with status: in_progress
  • If found — surface to user with live checklist and offer to resume from last incomplete item
  • Otherwise load only what is relevant: files, schemas, configs, prior decisions
  • Output a concise context summary: what was found, where it lives, what matters
3
Plan

Plan Architect

HERALD dispatches SA
  • SA analyzes project structure and checks agent-registry.json
  • SA classifies every task by risk level (safe / caution / destructive) and verification type (auto / human / none)
  • SA defines explicit acceptance criteria per task — not just what to build, but what correct looks like
  • SA runs dependency and architecture review — flags over-engineered approaches before any code is written
  • SA must surface at least one genuine challenge per plan — a risk, assumption, or alternative
  • SA estimates token cost for each plan option — shown at approval time
  • HERALD presents plans with Approach · Pros · Cons · Risks · Token estimate · Challenge — waits for user to select
  • Approved plan saved to plans/ with full checklist (all items: pending)
4
Synthesize

Prompt Synthesizer

  • HERALD writes a precise brief for each agent: objective, context, constraints, output spec, KB patterns
  • Context scoped to each agent only — nothing extra
  • No raw user input is ever passed to an agent
5
Dispatch

Dispatch Router

HERALD dispatches Agent Builder if needed
  • Compare plan requirements against agent-registry.json — missing agents trigger Agent Builder
  • Risk Gate — fires before any destructive task: surfaces what could be lost, safe default, and risky alternative. Silence = safe default.
  • Destructive Pattern Scan — scans generated artifacts (SQL, migrations, scripts) for DROP, TRUNCATE, DELETE without WHERE, rm -rf. Escalates risk level and re-fires Risk Gate if matched.
  • Context Checkpoint — at 75% context usage, SA writes a compact state summary, clears non-essential history, continues cleanly. Never relies on /compact.
  • Token Tracking — monitors cumulative usage; warns before budget is exceeded; user chooses continue, pause, or cancel.
  • Full output captured per checklist item — scanned for errors and destructive patterns before marked complete
  • Failures trigger retry with changed brief, or user escalation with specific options
6
Feedback

Feedback Loop

HERALD dispatches SA
  • Plan marked completed · SA dispatched to score
  • SA asks user: "Does the output match what was agreed in the handoff spec?"
  • Composite score calculated → reported to HERALD → written to plan file
  • ≥ 95% → pattern stored in knowledge-base.json
  • < 95% → failure dimensions tagged, no pattern stored

Safety & Quality Gates

Six structural gates that fire at specific points in the pipeline. Each addresses a documented failure mode. None can be skipped without explicit justification.

Risk Gate

Before any destructive task executes, HERALD presents what could be lost, the safe default, and the risky alternative. Silence always takes the safe default — consent is never inferred.

Destructive Pattern Scan

After artifacts are generated, HERALD scans for DROP, TRUNCATE, DELETE without WHERE, rm -rf, and similar patterns. Any match escalates risk level and re-fires the Risk Gate before execution.

Test-First Gate

For every logic or API task: test_writer → code_agent → test_runner. Acceptance criteria are encoded as tests before any implementation begins. Cannot be waived without explicit justification.

Human Verification Gate

For UI, visual design, and UX tasks: HERALD presents a binary checklist (pass/fail) to the user before continuing dispatch. Never fires for logic or data tasks.

Context Checkpoint

At 75% context usage, SA writes a compact state summary — what's done, what's pending, key decisions. Non-essential history is cleared. Dispatch continues from the summary. Never relies on /compact.

Anti-Sycophancy

Every plan must include at least one genuine challenge — a risk, a hidden assumption, or a viable alternative. "This looks good" alone is never an acceptable plan review. Agreement is not a default response.

Every execution is scored by the SA across four weighted dimensions. The composite score determines whether the pattern is stored in the knowledge base.

Self-Improvement Flywheel

HERALD gets smarter with every successful execution. Stored patterns let HERALD skip layers 1–3 on matched requests — making repeat task types faster and cheaper over time.

Rules

HERALD is the sole orchestrator

All agent communication routes through HERALD. No agent talks to another agent directly.

Single scope

Every agent does exactly one thing. Scope is defined at creation and does not expand.

No raw passthrough

HERALD never passes raw user input to downstream agents. All input is translated first.

Plan approval gate

HERALD never dispatches without the user approving a plan first. Always.

Plans are persistent

Every approved plan is saved with a live checklist. HERALD resumes in-progress plans on reinitialization.

Silence is safe

When a task is destructive and the user has no stated preference, HERALD takes the safe default. Consent for irreversible actions is never inferred.

Destructive tasks flagged early

Users see and acknowledge risk at plan approval — not mid-execution when it is too late to stop.

Layer 6 is mandatory

No execution closes without scoring. HERALD presents the Layer 6 prompt immediately when the last checklist item completes. Cannot be deferred.

No sycophancy

Every plan must include a genuine challenge. Agreement is not a default response. "This looks good" alone is never sufficient.

Config is king

herald.config.json overrides all flags and auto-classification. Lock down critical projects here.

Quality gate

Composite score ≥ 95% required to store a pattern. Keeps the knowledge base clean and trustworthy.

Environment-agnostic

HERALD operates identically regardless of the downstream environment — codebase, API, ERP, or any other system.

Architectural Limits

HERALD is an instruction layer. Its gates are instructions read and followed by the same model that executes the work. Under context pressure — long sessions, approaching token limits, a user bypassing a gate — the model may comply and skip enforcement. This is a fundamental property of instruction-following systems, not a flaw unique to HERALD.

What is reliable

Human-in-the-loop gates — plan approval and the Risk Gate — require explicit user confirmation. They do not depend on model compliance. Plan files and context.md create recoverable state that survives compliance failures.

What the hook provides

.claude/hooks/herald-safety.sh blocks rm -rf and DROP DATABASE/SCHEMA at the Bash tool level — before the model has any opportunity to comply or not comply. Fires regardless of model behavior, context length, or user pressure.

What the hook does not cover

Destructive patterns in generated files, DELETE FROM without WHERE, TRUNCATE, DROP TABLE — too context-dependent without high false positive rate. The Destructive Pattern Scan in Layer 5 handles these, but it is model-enforced.

The right mental model: HERALD makes the right behavior explicit and likely. The hook catches catastrophic Bash-level cases. Human approval gates are the reliable enforcement mechanism for everything in between. The system is as strong as the user's willingness to hold the gates.
